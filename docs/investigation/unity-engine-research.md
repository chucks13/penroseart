# Research: Unity engine landscape for penroseart

_Status: historical web-only research from 2026-05-18. Local project files were not inspected for this note. The repo currently uses Unity `6000.4.7f1`; verify Unity release/support/pricing pages again before using this as upgrade or licensing guidance._

## Summary
At the time of this web research, Unity’s stable Unity 6 line was Unity 6.3 LTS / Editor 6000.3; Unity’s latest release page showed 6000.3.15f1 released on 2026-05-08, with Unity 6.3 LTS supported until December 2027 and Unity 6.0 LTS through October 2026. This project has since been observed on Unity `6000.4.7f1`, so treat the release-current statements below as historical evidence, not current upgrade advice. The historical practical baseline from this research was Unity 6.3 LTS, URP 2D, .NET Standard 2.1, assembly definitions, locked packages, EditMode/PlayMode tests, and batch-mode CI builds. Unity canceled the game Runtime Fee; licensing is back to seat/subscription tiers with revenue thresholds and 2026 Pro/Enterprise price/package changes.

## Findings
1. **Historical fact as of 2026-05-18 — Unity 6.3 LTS was the current LTS line; 6.0 LTS was still supported but older.** Unity says Unity 6.3 LTS is available, supported for two years until December 2027, while Unity 6.0 LTS is supported through October 2026; Enterprise/Industry subscribers get one additional support year. Unity also says LTS releases are recommended for live-service games and teams locking production to a specific Unity version, while Update releases are production-ready and supported only until the next release is published. [Unity 6 release page](https://unity.com/releases/unity-6), [Unity 6 release support](https://unity.com/releases/unity-6/support)
2. **Confirmed fact — latest Editor release page showed Unity 6000.3.15f1.** Unity’s latest Editor release page was `Unity 6000.3.15f1`, released on 2026-05-08, with release notes and package changes listed for that patch. [Unity 6000.3.15f1 release notes](https://unity.com/releases/editor/latest)
3. **Confirmed fact — Unity 6 marketing versions map to 6000.x Editor versions.** Unity documents “Unity 6.3 (6000.3)” and release pages use patch identifiers such as `6000.3.15f1`; treat Unity 6.0 LTS as `6000.0` and Unity 6.3 LTS as `6000.3` when pinning CI/editor paths. [New in Unity 6.3](https://docs.unity3d.com/Manual/WhatsNewUnity63.html), [Unity 6000.3.15f1 release notes](https://unity.com/releases/editor/latest)
4. **Confirmed fact — Unity C# is Roslyn/C# 9.0, not current .NET 8/9.** Unity’s current manual says the Editor uses the Roslyn compiler and C# language version 9.0. Unity lists unsupported C# 9 features, notes record/init caveats, and explicitly says Unity serialization doesn’t support C# records in serialized types. [C# compiler and language version reference](https://docs.unity3d.com/Manual/CSharpCompiler.html)
5. **Confirmed fact — .NET Standard 2.1 is Unity’s default API compatibility level.** Unity supports `.NET Standard 2.1` and `.NET Framework 4.8 + additional .NET Standard 2.1 APIs`; Unity recommends .NET Standard for new projects because it has a smaller API surface, better cross-platform support, and moves more errors to compile time. Third-party libraries must be tested across target platforms/backends, and IL2CPP AOT doesn’t support runtime dynamic code generation. [API compatibility levels for .NET](https://docs.unity3d.com/Manual/dotnet-profile-support.html)
6. **Confirmed fact — URP 2D is Unity’s official 2D rendering path.** Unity’s 2D URP documentation covers 2D lighting, Pixel Perfect Camera, 3D GameObjects rendered in 2D URP scenes, and custom 2D renderer features/post-processing. Setup uses a 2D URP asset and 2D Universal Renderer asset, typically from the Universal 2D template. [2D game development in URP](https://docs.unity3d.com/Manual/2d-urp-landing.html), [Set up the 2D Renderer asset in URP](https://docs.unity3d.com/Manual/urp/Setup.html)
7. **Confirmed fact — Unity’s 2D tilemap stack is still first-class.** Unity’s Tilemaps docs cover tile palettes, painting into scenes, tile collisions, hex/isometric tilemaps, custom tiles/brushes, and Tilemap API references. URP 2D can light tilemaps, and the 2D Renderer Data asset controls transparency sorting for isometric/pseudo-depth setups; SRP batching is supported with compatible Tilemap Renderer modes. [Tilemaps](https://docs.unity3d.com/Manual/tilemaps/tilemaps-landing.html), [Tilemap Renderer with URP 2D lighting](https://docs.unity3d.com/Manual/urp/2d/tilemap-renderer-2d-renderer.html)
8. **Confirmed fact — Unity 6.3 adds notable 2D/performance tooling.** Unity 6.3 adds low-level 2D physics APIs based on Box2D v3, 3D renderers sorted/lit as 2D in URP, Sprite Atlas Analyzer, and 2D animation performance improvements. These are relevant if penroseart uses large sprite atlases, hybrid 2D/3D visuals, or custom 2D physics. [Unity 6.3 LTS announcement](https://unity.com/blog/unity-6-3-lts-is-now-available), [New in Unity 6.3](https://docs.unity3d.com/Manual/WhatsNewUnity63.html)
9. **Confirmed fact — Package Manager state belongs in project manifests/lock files.** Unity Package Manager reads `Packages/manifest.json` for direct dependencies, registries, testable packages, and pinned packages; `Packages/packages-lock.json` records dependency resolution for deterministic package sets and Unity says to put the lock file under source control. Unity 6.3 also adds package signatures and package authoring/pinning improvements. [Project manifest file](https://docs.unity3d.com/Manual/upm-manifestPrj.html), [Lock files](https://docs.unity3d.com/Manual/upm-conflicts-auto.html), [New in Unity 6.3 — Package Manager](https://docs.unity3d.com/Manual/WhatsNewUnity63.html#package-manager)
10. **Confirmed fact — Burst/Jobs/DOTS are mature but should be introduced for measured performance needs.** Burst compiles compatible C# / HPC# to optimized native CPU code through LLVM, mainly for Jobs and Burst-marked static methods. Unity’s Job System provides safe multithreaded worker-thread execution and is designed to pair with Burst. DOTS/Entities combines Entities, Jobs, Burst, Collections, Mathematics, and optional ECS packages such as Unity Physics, Entities Graphics, and Netcode for Entities. [Burst compiler](https://docs.unity3d.com/Packages/com.unity.burst@latest), [Job system overview](https://docs.unity3d.com/Manual/job-system-overview.html), [ECS packages](https://docs.unity3d.com/Packages/com.unity.entities@6.5/manual/ecs-packages.html)
11. **Confirmed fact — Runtime Fee is canceled for games; terms removed the fee language.** Unity canceled the Runtime Fee for game customers effective immediately on 2024-09-12 and reverted to seat-based subscriptions. The 2024-10-10 Editor Software Terms update removed Runtime Fee language; Unity 6 requires accepting those updated terms, while prior accepted terms can remain for a named Editor version if you keep using that version. [Unity Runtime Fee cancellation](https://unity.com/blog/unity-is-canceling-the-runtime-fee), [Editor Software Terms update](https://unity.com/blog/terms-update-runtime-fee-cancellation)
12. **Confirmed fact — current licensing thresholds/pricing matter before commercial release.** Unity’s 2026 pricing page says Personal is available up to $200k annual revenue/funding with optional Unity 6 splash screen; Pro is required over $200k and listed at $2,310/year per seat or $210/month per seat; Enterprise is required over $25M and custom-priced. Unity also says Pro/Enterprise had a 5% increase starting 2026-01-12, Havok Physics is no longer included with Unity 6.3 LTS Pro/Enterprise/Industry plans, and DevOps free tiers expanded in 2026. [Unity pricing updates](https://unity.com/products/pricing-updates)
13. **Guidance — organize penroseart as a maintainable Unity C# codebase, not a monolithic `Assembly-CSharp`.** Use assembly definitions for runtime, editor-only, tests, and reusable modules; Unity says asmdefs reduce unnecessary recompilation, clarify dependencies, and make code easier to debug/refactor. Use a project style guide for naming/formatting/small classes and methods; Unity’s C# style guide frames this as maintainability guidance rather than an engine requirement. [Assemblies in Unity](https://docs.unity3d.com/Manual/assembly-definitions-intro.html), [Organizing scripts into assemblies](https://docs.unity3d.com/Manual/assembly-definition-files.html), [Unity C# Style Guide](https://unity.com/resources/c-sharp-style-guide-unity-6)
14. **Guidance — keep Unity assets/version control reproducible.** Commit `.meta` files because Unity stores asset IDs and import settings there; losing a `.meta` file breaks references. Use visible meta files with external VCS, commit `Packages/manifest.json` and `Packages/packages-lock.json`, and avoid manually editing the lock file. [Asset metadata](https://docs.unity3d.com/Manual/AssetMetadata.html), [Version Control settings](https://docs.unity3d.com/Manual/class-VersionControlSettings.html), [Lock files](https://docs.unity3d.com/Manual/upm-conflicts-auto.html)
15. **Confirmed fact + guidance — Unity Test Framework and batchmode builds are CI-ready.** Unity Test Framework supports EditMode/PlayMode tests via Test Runner, command line, or code and uses a custom NUnit 3.5-based framework. Unity documents `-runTests -batchmode -projectPath ... -testResults ...`; for builds, Unity recommends `-batchmode`, `-quit`, `-logFile`, and explicit `-buildTarget` or `-activeBuildProfile`, with separate Unity invocations per target for reliable batch builds. [Testing your code](https://docs.unity3d.com/Manual/test-framework/test-framework-introduction.html), [Run tests from command line](https://docs.unity3d.com/Manual/test-framework/run-tests-from-command-line.html), [Build a player from command line](https://docs.unity3d.com/Manual/build-command-line.html)

## Practical baseline for penroseart
- Historical recommendation at the time of research: prefer **Unity 6.3 LTS / 6000.3.x** for new work or a planned upgrade unless project stability argues against moving. Current repo state is Unity `6000.4.7f1`; re-check Unity release notes before changing editor versions.
- Prefer **URP 2D** for art/2D rendering; use Pixel Perfect Camera, Sprite Atlases, Tilemaps, 2D lights, and the Unity 6.3 Sprite Atlas Analyzer where relevant.
- Keep scripting conservative: **C# 9.0**, **.NET Standard 2.1**, no serialized C# records, no unsupported C# 9 features, and verify third-party libraries under IL2CPP/AOT for target platforms.
- Add asmdefs early: `PenroseArt.Runtime`, `PenroseArt.Editor`, `PenroseArt.Tests.EditMode`, `PenroseArt.Tests.PlayMode` or similarly small namespaced modules.
- Use Burst/Jobs only for profiled CPU hotspots; do not adopt DOTS/Entities by default for a small/medium 2D project unless data-oriented scale is a core requirement.
- CI shape: pin the Unity Editor version, restore exact packages from manifest/lock, run EditMode tests, run PlayMode tests where useful, then build one target per Unity batchmode invocation with logs captured.

Example CI commands to adapt:

```bash
# Tests
/Applications/Unity/Hub/Editor/6000.3.xx/Unity.app/Contents/MacOS/Unity \
  -runTests -batchmode -projectPath "$PWD" \
  -testResults build/test-results.xml -testPlatform EditMode -quit \
  -logFile build/unity-test.log

# Build via custom static method
/Applications/Unity/Hub/Editor/6000.3.xx/Unity.app/Contents/MacOS/Unity \
  -executeMethod BuildScripts.BuildMacOS \
  -buildTarget StandaloneOSX -batchmode -quit \
  -projectPath "$PWD" -logFile build/unity-build.log
```
