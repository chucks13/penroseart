What the branch does

Teaches the Director to cast event-aware cues. The casting seam now classifies each scheduled cue as Ordinary / Fill / Drop by comparing the current Cue Mark against BeatManager's live Fill/Drop timing — without creating or moving Cue Marks — and prefers an event-capable Transition from the deck only when its Runway/Tail can still serve that Cue Mark. The Repertoire flags shrink from {Fill, Drop, RespondsToEnergy} to {Fill, Drop}.

Findings

1 · Dead production API: TransitionDeckSelection.TryPullPreferred

MINOR · YAGNI

Assets/core/Switching/EffectDeckSelection.cs

Problem   Five tests exercise TryPullPreferred, but nothing in production calls it.

Why   The Director needs the rotation deferred until a cue actually fires, so it uses the two-phase TryFindPreferred + PullAt. The combined call only mirrors the effect-deck version for symmetry.

  • Remove it and its five tests — the leverage is the two-phase split, not the combined call.
  • Or keep it with a one-line comment stating it is retained for parity.

2 · Duplicated PreferredRepertoireFor mapping

MINOR · LOCALITY

SyncedCueIntent.cs:257  ·  Director.cs:780

Problem   The identical CueEventIntent → Repertoire switch lives in two modules and must be kept in sync by hand.

switch (eventIntent) {
  case CueEventIntent.Fill: return Repertoire.HandlesFill;
  case CueEventIntent.Drop: return Repertoire.HandlesDrop;
  default:                  return Repertoire.None;
}

Fix   One shared helper (public static on SyncedCueIntent or an extension on CueEventIntent); both call sites use it. Locality: the mapping lives in one module.

3 · Transient writes in Director.TryStartSyncedCue

MINOR · CLARITY

Assets/core/Switching/Director.cs:612–618

Problem   The deck-transition block writes state that is overwritten within the same method by CommitSentCue → StageNextTransition. Only PullAt's rotation survives.

if (transitionSelection.DeckIndex >= 0) {
    nextTransitionIndex = TransitionDeckSelection.PullAt(transitionDeck, ...); // overwritten below
    controller.currentTransition = nextTransitionIndex;                  // overwritten by CommitSentCue
    transitionIndex = nextTransitionIndex;                              // already equal — self-assign
}

Fix   Reduce to the rotation side effect with a comment, e.g. // consume the preferred card so the fresh stage below won't redraw it. Not a bug — the cue is built from the still-correct local transitionIndex/repertoire.
