In one paragraph

The legacy stack is a 2015 copy of thomasfredericks/UnityOSC wired to a TouchOSC-style tablet control surface. A background thread listens on UDP 6969, parses OSC packets, and hands every message to one root handler on the Unity main thread. That handler fans the message out to three page handlers — Controller page 1, camera page 2/6, drums page 3 — and collects reply messages, which go back out to 192.168.1.255:6161. It is a bidirectional remote control, not a data feed: it owns master brightness, the NYE overlay toggle, direct effect selection, the effect dwell time, and drum-overlay triggers, and it mirrors that state back to the surface once per frame so the tablet's faders and buttons stay in sync.

It shares nothing with the RaveSystem stack — different port, different files, different parser, different consumers. The two only meet as sibling components added to the same GameObject in Controller.Start().

3 · Anatomy of the two files

Assets/OSC.cs

Vendored UnityOSC v1.01 (2015-05-27), itself derived from the Make Controller Kit library — the provenance comment is still at the top of the file (OSC.cs:1-5).

  • OscMessage — string address plus an untyped ArrayList values, with GetInt/GetFloat coercing between int and float and logging "Wrong type" for anything else (:316-402).
  • OscMessageHandler — the void h(OscMessage) delegate the whole stack is built on.
  • class OSC : MonoBehaviour — a full second copy of the reader. Only its static parse/serialize helpers are ever called; see §8.

Assets/OSCReader.cs

The half of the library that actually runs.

  • UDPPacketIO — a UdpClient pair. The receiver binds IPAddress.Any:localPort; the sender is unbound and targets host/port per call. Sockets open lazily on first send or receive (:21-206).
  • OSCReader : MonoBehaviour — Awake() builds the transport, allocates a single 1000-byte buffer, and starts a background Read() thread (:237-259).
  • Update() drains the queue under ReadThreadLock, calling the all-message handler for each message (:284-312).

Wiring and configuration

Controller.Start() adds the component at runtime and registers the root handler (Controller.cs:1413-1414): 

osc = gameObject.AddComponent(typeof(OSCReader)) as OSCReader;
osc.SetAllMessageHandler(OscHandler);
raveOsc = gameObject.AddComponent<RaveOscReceiver>();   // the other stack, UDP 7000

Neither OSC.cs nor OSCReader.cs appears by GUID in Assets/Scenes/SampleScene.unity, so nothing overrides the serialized defaults. The ports below are the hardcoded field initializers, and they are what runs.

4 · What the parser supports

Receive

ExtractMessages() switches on the first byte: '/' is a single message, '#' is checked for the literal #bundle, then skips 16 bytes and walks the length-prefixed elements (OSC.cs:908-933).

ExtractMessage() reads the address, the type tag, then only s, i, and f — ints big-endian, floats byte-reversed through a BinaryReader (:946-990).

Blobs, timetags, bools, and every other OSC 1.0 type are silently skipped without advancing the read index, which desynchronizes the rest of the message.

Send

One reply goes out as a plain message; two or more are wrapped in a #bundle with per-element length prefixes (OSC.cs:782-810).

Every reply built by PenroseArt is a single float — Controller.makemessage(address, value) (Controller.cs:930).

Vendored quirk: the comment says "write a null timestamp" but the code runs packet[index++]++ eight times, so the timetag ships as 01 01 01 01 01 01 01 01, not zero. Harmless here because the receiving surface ignores it, and the reader skips a fixed 16 bytes anyway.

5 · Every inbound address, and what it does

Controller.OscHandler() (Controller.cs:912-926) runs every message through all three page handlers in order, then stamps the message text into the on-screen HUD for 20 frames and flushes any replies.

Page 1 — Controller.OSCpage1 (live)

AddressArgEffectReply
/1/vscroll1 float Master brightness. brightness = Lerp(255, 0, v) — inverted: fader at 0.0 is full output, 1.0 is black. This byte multiplies every channel in both the serial and E1.31 output paths (Controller.cs:684, :712) and is forced to 0 when displayOn is false. —
/1/nav1* int == 1 Toggles NYE, which replaces the whole render with the sparse white-pixel overlay (Controller.cs:1606-1614). Prefix match, so any /1/nav1… address hits it. —
/1/push<n> int == 1 button = n - 1. Button 23 (i.e. /1/push24) flips keyboardBase; anything else calls JumpToEffect(button + keyboardBase, effectTime), which routes into Director.ShowNow() when the Director exists (Controller.cs:777-797). This is the one place the legacy stack reaches into the modern switching model. echo, 1.0
/1/hscroll1 float Effect dwell time, as a coarse ladder of sequential ifs: == 1.0 → 3600s, < 0.87 → 120s, < 0.62 → 10s, < 0.37 → 5s, < 0.12 → 1s. Later tests overwrite earlier ones, so the smallest matching bucket wins. —
/ping any State mirror. Also sent to itself once per frame — see §6. /1/vscroll1 + one /1/push<n>
/beat — Branch exists and is empty { } (Controller.cs:914-915). Beat now arrives over RaveSystem on 7000. —

Page 3 — drums.OSCpage3 (live)

AddressArgEffect
/disk int 1-5 Fires an expanding ring overlay: rings[i-1] = 5f (drums.cs:225-231). The intensity argument is accepted and ignored.
/3/toggle<n> int == 1 Fires drum pad n-1 (pads 0-4): hits[i] = 5f; speed[i] = 0f (drums.cs:211-218).
/3/rotary*, /ping — Empty branches, kept as placeholders.

Separate from OSC, drums also runs its own raw UDP listener on 8500 for OpenPixel-style trigger packets (drums.cs:83). Same overlay, different wire — not part of this stack.

Pages 2 & 6 — CameraReader.OSCpage2 (inert)

SampleScene.unity serializes useCamera: 0, so cameraOverlay is never constructed and this whole page is unreachable in the shipped scene (Controller.cs:919, :1424-1429). Documented here because it is fully implemented and one bool away from live.

  • /2/fader1…9, /2/rotary1 — write the ten-element settings[] array that tunes the webcam overlay.
  • /2/push1…8 — reset the matching setting to its default and echo the new knob value.
  • /2/nav4, /2/nav5 — cycle camera device 0 and 1.
  • /6/toggle<33+n> — a 3×8 radio grid; selecting one clears the previous member of that row and echoes both states.
  • /2 — page-open handshake: dumps all ten knobs and the three active toggles.
  • /ping — round-robins one of 34 state values per call (10 knobs, then 24 toggles).

6 · The outbound heartbeat

Controller.OSCping() is called unconditionally at the end of every Update() (Controller.cs:1687). It fabricates a local /ping message and pushes it through the same page handlers the network uses, so the reply path is driven by the render loop rather than by the tablet.

Per frame, at Application.targetFrameRate = 60, that produces:

  • one packet carrying /1/vscroll1 = 1 - brightness/255, so the fader tracks brightness changed by keyboard, telnet, or the scene slider;
  • one packet carrying /1/push<pingIndex+1> = 1 or 0, lighting exactly one button of the effect matrix per frame and cycling pingIndex through effects.Length — the whole matrix refreshes in about effects.Length / 60 seconds;
  • plus /1/reset whenever the current effect index is out of range.

The current index is read from switcher.CurrentEffectIndex when a Switcher exists, falling back to currentEffect — so the legacy surface reflects the modern switching model rather than a stale copy of it.

Roughly 120 UDP packets per second leave the process whether or not a control surface is listening, and nothing throttles or gates it.

7 · What it actually controls today

Live

  • Master output brightness (serial and E1.31 paths)
  • NYE overlay on/off
  • Direct effect selection, via Director.ShowNow
  • Effect bank toggle (keyboardBase)
  • Effect dwell time (effectTime)
  • Drum pad and ring overlay triggers
  • The transient bottom-HUD message line
  • Continuous state mirroring back to the surface

Not its job

  • Beat, BPM, transport, loop state — RaveSystem on 7000
  • Cue sheets, planning, switching decisions — Director/Switcher
  • External pixel sources — PixelReceiver, UDP 7778
  • Frame output — SerialOut / E1.31
  • Camera overlay — implemented, disabled in the scene

9 · Sharp edges

Found by reading; none of these were reproduced at runtime. Ordered by how much they would hurt.

A malformed /1/push address can wedge the message queue permanently.

high

int.Parse(om.address.Substring(7)) (Controller.cs:864) throws on any /1/push… address that is not followed by digits. The throw unwinds out of OSCReader.Update() before messagesReceived.Clear() (OSCReader.cs:309), so the offending message stays queued and is re-dispatched — and re-throws — every frame from then on. Unity swallows the exception per frame; the surface just stops responding.

Same shape applies to /3/toggle and /6/toggle, and to GetInt/GetFloat on an argument-less message, which would throw on the values[0] index.

The OSC bank toggle and the keyboard bank toggle disagree.

likely bug

Both flip the same keyboardBase flag, but the keyboard path offsets by keyboardBase * 23 (Controller.cs:1567) while the OSC path offsets by keyboardBase alone (:870). Pressing the OSC bank button therefore shifts the button matrix by one effect, not by a bank of 23 — and the ping feedback, which compares raw indices, will light the wrong button while the bank is flipped.

Replies are addressed to a subnet this machine is not on.

verify

outIP is hardcoded to the directed broadcast 192.168.1.255, while the documented workstation LAN is 192.168.10.0/24. If the installation network matches the workstation's, the entire outbound half of this stack — the whole state-mirroring heartbeat — is landing nowhere. Nothing in the code reads back a delivery result, so this would fail completely silently. Worth confirming against the real installation network before treating any of §6 as working.

Thread.Abort() on shutdown.

portability

Close() aborts the reader thread and only then closes the socket (OSCReader.cs:332-344), while that thread is parked in a blocking UdpClient.Receive. It works today because ProjectSettings.asset names no Standalone scripting backend, leaving the Mono default. Under IL2CPP Thread.Abort is not supported, and the shutdown path would throw instead of stopping the thread. Closing the socket first and letting Receive fault out is the conventional fix.

The dispatch lock is held across the entire handler chain.

design

Update() holds ReadThreadLock while running OscHandler, which can reach as far as Director.ShowNow and a full effect start. The reader thread blocks for that whole span, and any packet arriving meanwhile waits in the socket buffer. Harmless at this traffic level; a hazard if the handler chain ever grows.

Fixed 1000-byte buffer, silently truncating.

robustness

ReceivePacket copies min(buffer, incoming) and reports the truncated length (OSCReader.cs:143-158). A larger bundle is cut mid-message and the parser walks the remains. The send path has the same 1000-byte ceiling with no bounds check on the reply bundle.

No sender filtering.

exposure

The socket binds IPAddress.Any and the handler ignores the sender endpoint entirely. Any host that can reach UDP 6969 can black out the wall or change the effect. Appropriate to a closed installation LAN; worth knowing before the machine sits on anything wider.

10 · Open questions

  • Is there still a control surface? The address vocabulary (/1/push*, /2/fader*, /6/toggle33+, page-open handshakes) is TouchOSC's default layout scheme, but the layout file itself is not in this repo. Whether a tablet is still pointed at this port is a fact only you have.
  • What is the installation subnet? Resolves sharp edge #3 outright, and decides whether the per-frame heartbeat is doing anything at all.
  • Is the camera overlay retired or paused? useCamera: 0 makes roughly 80 lines of page 2/6 handling and the whole CameraReader unreachable. If it is retired, that is the largest single cut available here.
  • Nothing was run. This is a source read — no Unity session, no packet capture, no log evidence. Every claim traces to a file and line above; none of them were observed executing.
