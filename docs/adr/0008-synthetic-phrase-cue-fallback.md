# Beat-only mode cues from a synthetic phrase window, not real Track Phase

Tracks loaded on the Pioneer gear may or may not carry preprocessed Track Phase data, but a phrase-less track still broadcasts a usable clock (beat, beat-in-bar, total beats, bpm). Today that case — On-Air Timing's beat-only frame with no Track Phase (the `TrackPhaseActive == -1` branch in `CuePlanner.Plan`) — produces an unlocked frame with no Cue Mark, so the Director idles in Synced Mode and issues no cues for the whole track, waiting for phrase data that may never arrive. We keep cueing in this fallback by synthesizing a rolling 64-beat phrase window from the running 4-count grid and feeding it through the existing `CueSheet.Build`, so beat-only sequencing inherits the real path's cue character instead of going dark. This is a deliberate fallback that holds until a phrase-bearing track loads (ADR-0005 Cue Sheets, ADR-0006 phase determiner, ADR-0007 mode authority).

## A synthetic 64-beat phrase window feeds the existing Cue Sheet builder

When the clock is running but no Track Phase is present, the Director fabricates a `PhraseWindow` and runs it through the same `CueSheet.Build` the real path uses, rather than re-deriving cue selection anywhere new. The window is anchored on the grid "the one" that `PhaseLock` already holds (its 16-beat offset), so every generated Cue Mark lands on a downbeat, and it stays aligned through a transient mid-track phrase dropout instead of snapping to a generic beat-mod-16 grid. Length is 64 beats — four 16-beat Phases — because that gives the random selection real interior choices (up to three) and equals the existing 64-beat maximum-gap bound, so the mandatory final boundary alone already caps silence. Reusing `CueSheet.Build` means the fallback gets its two defining traits for free: the random phase-subset selection keeps cues off most phases (not every 16 beats), and the mandatory end plus 64-beat gap fill keep silence bounded.

## The window rolls on its mandatory final boundary and re-rolls fresh each pass

A real phrase rolls over at a feed-supplied boundary; the synthetic window has no real end, so its mandatory final Cue Mark doubles as the roll point — when it is consumed, the window advances by 64 beats to the next grid one. Each advance rebuilds the sheet with a fresh random subset rather than reusing the same-length sheet, so a long phrase-less track keeps varying its cue placement instead of looping one fixed pattern. Within a single window the sheet is stable, so the random pattern is not re-rolled every frame.

## A distinct Synthetic Phrase timing source keeps fabricated and real sheets apart

The fallback frame reports its own `TimingFrameSource` (Synthetic Phrase), separate from the real `CueMark`/`TrackPhaseBoundary` sources. This is load-bearing, not just diagnostic: `CueSheet.Matches` keys reuse on phrase length alone, so without a distinct source a synthetic 64-beat sheet would be silently reused for an incoming real 64-beat phrase, ignoring the real phrase's structure. Tagging the source lets the planner reset cleanly across the synthetic↔real boundary, and labels the HUD so a fabricated cue is never mistaken for a real phrase boundary. The fallback-to-phrase handoff otherwise rides the existing re-anchor path that already promotes a fresh structural anchor over a grid/coast one, which is why a beat-only track can hand off to a phrase-bearing track mid-set without new transition machinery.

## Rejected: idle until phrase data arrives, or cue on every 16-beat Phase

Leaving the beat-only branch unlocked — the current behavior — is the defect this fixes: a phrase-less track produces no cues at all, which is the opposite of a fallback. Driving cues off the bare 16-beat grid (the existing grid-fallback landing target) does keep cueing, but it fires on every Phase, far denser and more mechanical than wanted; the whole point is sparse-but-bounded selection, which only `CueSheet.Build` expresses. Re-implementing that random-subset-plus-gap-fill selection outside the Cue Sheet to avoid fabricating a window would duplicate the one set of rules ADR-0005 deliberately centralized, so the synthetic window pays a small fabrication cost to keep cue selection in exactly one place.
