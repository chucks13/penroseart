Executive verdict

The architecture got simpler. The musical behavior is not yet faithful.

There are no longer five or six live systems trying to count the same switching fact. The prepared-execution branch was discarded, the BeatManager Grid-start counter was added and then removed, Transition tags were deleted, stillness has one runtime owner, and all three anomalies now use one doorway.

The remaining problem is narrower and more concrete: the runtime cannot always identify the exact Grid seam, then compensates with heuristics that allow decisions and impacts inside a Grid. The planner also throws away real structure data. Those are correctness defects, not a reason to introduce another coordination system.

One missing fact

A sampled position is not an exact seam event

The wire publishes movable current state and may arrive late or out of order. The code has no authoritative “the closing seam happened now” fact, so exact execution is guessed.

Forensic findings

Every discrepancy found

Severity reflects likely show impact and contract strength, not file size. The first six should be resolved before cosmetic cleanup.

Critical · timingObserved incident path

1. A late Grid update moves Grid-start thinking inside the Grid

Tick returns immediately when the absolute beat has not changed, before observing the Grid edge. If beat 65 arrives with stale Grid 16 and Grid 1 arrives later in the same beat, that frame is ignored. If the next observed state is beat 66/Grid 2, the descending position is treated as the seam and Think(66) runs one beat late.

The regression test explicitly accepts this result. That saves a missed decision but violates “think at the Grid start” and can miss a runway or scheduled mark.

Evidence: Switcher.cs lines 344–387 · SwitcherExecutionTests.cs, ALateGridDatagramAtAGridStartStillThinks.

Critical · direct model violation

2. Fresh off-plan cues bypass runway scheduling

At a Grid-start anomaly the code calls Perform(beat, beat, answer, OffPlan). The transition begins immediately, so its authored Impact occurs runway beats later—inside the current Grid—not at the seam closing that Grid. A short Grid can end before the runway does.

The current model now says the opposite in explicit terms: runway on this Grid, impact at its closing seam, tail on the next, never a raw start.

Evidence: Switcher.cs line 522 · switching-model.md, “The Switcher’s job.”

High · whole-plan gap

3. The unanalysed end of a real track receives no plan

TrackCueSheet.Build constructs boundaries only from the phrase list and never reads StructureValues.TotalBeats. The wire contract permits analyzed phrases to end before the track does. The remaining track can therefore contain no planned marks, despite the Cue Sheet being defined as the whole track’s plan.

Existing test helpers set TotalBeats to the last phrase end, hiding the production case.

Evidence: TrackCueSheet.cs, Build/GridBoundaries · osc-client-contract.md, analyzed structure completeness.

High · musical truth

4. Anchor extraction rewrites the wire’s Drop and Fill facts

  • A present DropLandingBeat is replaced with phrase.StartBeat.
  • The continue after a Drop discards a Fill on the same phrase.
  • A Fill followed by any Drop phrase is suppressed, even when the analyzed landing is offset.
  • The Fill start is ignored; only a fabricated endpoint after the phrase is retained.

A transition can cross the actual Drop landing or Fill window the plan promises to clear. The OSC contract explicitly says analyzed Drop landings may be several beats after the phrase start and defines Fill from fill_start_beat through phrase end.

Evidence: TrackCueSheet.cs lines 602–627 · osc-client-contract.md.

High · silent guarantee loss

5. Capability failures are silently converted into ordinary show behavior

If no effect advertises an Anchor capability, OwnableAnchors drops that Anchor and returns its landing to the ordinary candidate pool. If two nearby Anchors share one carrier and no effect supports the combined capabilities, Deal can resolve only the first while the tests inspect only returned resolutions.

This is speculative fallback behavior for catalogs that the current production catalog does not have. It weakens an absolute artistic rule and makes a future catalog edit fail silently. A plain validation error is simpler and safer.

Evidence: TrackCueSheet.cs, OwnableAnchors and Anchor dealing · TrackCueSheetTests.cs.

High · unresolved contract

6. Show Now can replace a move that the model calls fire-and-forget

Calling StartTransition while a transition is rendering replaces it and uses the prior target as the new source. Director.ShowNow calls that method directly. A test locks this replacement behavior.

The docs also describe Show Now as happening “at once,” so this is a real product decision—not a safe refactor assumption. Hunter must choose whether Show Now is the sole emergency interruption or whether every move truly completes.

Evidence: Director.cs, ShowNow · Switcher.cs, StartTransition · test StartTransitionWhileRenderingReplacesMoveFromPreviousTarget.

Medium · ceiling

7. “Never beyond 64 beats” is not actually an invariant

The planner says fit outranks the 64-beat ceiling on a degenerate boundary lattice and delegates the result to runtime Stillness. Tests check only gaps between marks that were emitted—not the track run-in, run-out, omitted tail, or every possible constrained plan.

The same 64-beat idea is represented as beats in planning and four Grids at runtime, then converted through a hard-coded 16-beat round trip for off-plan take probability. Short Grids make those facts different.

Evidence: TrackCueSheet.cs lines 151–166 and 497–594.

Medium · short Grids

8. “Next mark within 16 beats” does not mean “this Grid’s closing seam”

NextBoundaryMark selects the first future mark within 16 beats. On short Grids, several real Grid seams can fall in that window. The Switcher may decide a later mark one or more Grids early, consuming a staged override or Hold decision at the wrong think even if the authored fire beat remains correct.

This is an information problem disguised as arithmetic: the Switcher needs the immediate closing seam, not a nominal 16-beat window.

Evidence: Switcher.cs, NextBoundaryMark.

Medium · ambiguous edge

9. The repeated 1→1 rule cannot distinguish music from a lagging datagram

The crossing predicate treats gridBeat == 1 && lastGrid == 1 as a new Grid to support consecutive one-beat phrases. The same observation can also be a repeated/stale position 1. If Think already ran, the heuristic can double-count stillness or ask twice.

No test covers both interpretations. More flags cannot resolve an event that the input does not identify.

Evidence: Switcher.cs lines 382–387.

Medium · tiny catalogs

10. Off-plan exclusion falls back to the excluded effect

Bag.DealPreferred returns the top card when no card satisfies “not on wall and not moving toward.” In a one- or two-effect catalog, a fresh cue can therefore select exactly the effect the model says it must never return.

The current production catalog is large, so this is latent. The simplest answer is an explicit catalog precondition, not a clever fallback.

Evidence: TrackCueSheet.cs lines 274 and 907 onward.

Low · semantics

11. One frozen value represents several different answers

CueDecision.Frozen means ride-through, no focus sheet, or a held-wall refusal. The Live panel renders every non-perform result as “RIDE,” which can misreport a Hold or absent plan during diagnosis.

No new decision hierarchy is warranted. A diagnostic reason can be derived at the decision site or the label can simply say “NO CUE.”

Evidence: Director.cs, DecideOffPlanCue · PenroseTuningWindow.cs.

Low · mutable mirror

12. Controller.currentTransition mirrors state with five production writers

The field is written by four Director paths and one Switcher path, then used mainly as a startup seed plus inspector/test state. It is a pre-existing second mutable representation of “current/next transition,” and it can drift.

Delete only after identifying the one production read and choosing the existing owner’s value. Do not use it as a reason to restructure Controller.

Evidence: Controller.cs, Director.cs, and Switcher.cs.

Low · dead surface

13. Several public members exist only for tests or duplicate status

  • Four Director aliases have no external semantic references: next effect, next transition, and the two Hold properties.
  • Switcher.Sheet has no production caller; six tests read it.
  • Deck.TryFindPreferred is production-public but tests-only.
  • CuePlanMark.FiredAtBeat has a public setter used to construct an otherwise impossible test state.
  • SheetSalt is publicly mutable mainly for deterministic tests.

These are good hard-cut candidates. They do not justify interfaces or a new construction framework.

Low · naming drift

14. Code still calls a seam an absolute beat

CuePlanMark.Beat, parameter names such as boundaryBeat, and XML comments describe the mark as a beat. The current glossary now says the seam is not a beat; its opening beat is only the label.

If renamed, make one hard cut across code and tests. Do not introduce a GridBoundary object merely to encode the wording.

Low · shallow representation

15. Small data shapes add friction but are not urgent architecture

One-field EffectDescriptor/TransitionDescriptor values cause repeated projection loops. smallRunway and smallTail travel together through planner methods even though TransitionRepertoire already owns both. A default Cue Sheet is partially formed, so callers repeat generation/null checks.

Collapse these only when touching their behavior; a cleanup-only type rewrite would create churn without show value.

Low · process

16. Test scaffolding and documentation are heavier than the runtime seam

Three fixtures create Controller GameObjects and reflect into the private Singleton instance. Ten touched TrackCueSheetTests methods lack the repository-required XML scenario/outcome comments. The fixtures are repetitive, but tests alone are not a production caller for new Director/Switcher interfaces.

Consolidate fixture setup locally if the files are touched. Do not narrow production construction solely to make tests prettier.

Suggested path

Fix truth first. Delete second. Do not build a new coordination system.

1

Decide the authoritative Grid-seam fact

The current sampled Beat/Grid state cannot distinguish an exact seam from delayed or repeated state in every case. Choose where coherence lives before changing counters.

2

Decide whether Show Now may interrupt

“At once” and “every started transition completes” cannot both be unconditional. Name the one exception or remove replacement behavior.

Recommended order
  1. Make seam observation coherent. As a necessary first step, observe a same-beat 16→1 Grid update before the once-per-beat execution return. Treat that as insufficient for the next-beat/Grid-2 case; solve that at the authoritative input seam, not with more Switcher guesses.
  2. Put fresh off-plan cues through the existing runway scheduler. Schedule impact at the Grid closing seam and require the selected transition to fit that Grid. Extend the existing scheduled state first; introduce a private record only if it deletes parallel branches.
  3. Make TrackCueSheet consume all structure truth. Extend ordinary Grid boundaries through TotalBeats. Use actual Drop landings and the full Fill interval. Preserve both when one phrase contains both.
  4. Replace silent catalog fallbacks with plain validation. If the production catalog cannot honor an Anchor or fresh-cue exclusion, fail the sheet/catalog clearly. Do not quietly reinterpret the model.
  5. Replace tests that pin wrong behavior with independent oracles. Assert exact seams and source structure values, not results computed by the same implementation.
  6. Run the real wall verification in issue 100. Only then publish the local branch and reconcile issues 108–110 with the commits that actually reached GitHub.
  7. Perform one deletion pass. Remove dead aliases, test-only public surfaces, the transition mirror, primitive beat/Grid conversion, and redundant fixture setup where each deletion is proven.
