Standalone mode has no single source of truth

Follow-up to the on-air-timing branch review's Critical finding. Scope: every site in the runtime that decides or consumes "are we in standalone (no-beat) mode?". Reviewed on master at 19f686e8 (the merged branch). Conclusion verified against code, not docs.

Conclusion: the standalone/synced decision is not one decision. It is re-derived independently at five places from three different signals at three strictness levels. The effects and the Director read different signals, so they disagree in exactly one state — live OSC present, no usable clock — and in that state the Director freezes while the effects correctly run standalone. This is a missing seam, not a missing wire.

Symptom

Director sequencing freezes on no-clock OSC

Root cause

Mode re-derived from 3 signals, no authority

Divergence

Effects read IsActive; Director reads IsLiveSource

Fix shape

One predicate, owned by BeatManager

Legend: solid box = module · dashed line = seam · red edge = signal read by the wrong consumer · thick box = proposed deep module.

Three signals, one question

Everything downstream is trying to answer one question — is there a usable musical clock right now? — but each consumer asks a different proxy. The proxies agree most of the time, which is why this hid until the on-air-timing work made the Director act on the wrong one.

The Director's mode branch keys off IsLiveSource (transport). Every effect keys off IsActive (usable clock). Those are not the same predicate, and nothing reconciles them.

The trace at Director.cs:674 already prints both signals side by side: MODE …->… live={IsLiveSource} beat={Beat}. The author knew they were two different things; the mode branch just picked the wrong one. MODE Synced live=True beat=null is a representable, logged state — and it is the freeze.

The world is tri-state; the Director's branch is binary

ClearToNoBeat (BeatManager.cs:731–742) and the live-sentinel path both leave bpm = -1, so IsActive is false in two different worlds. The only thing separating them is liveBeatActive. That makes three real states, and the consumers map them differently.

State IsLiveSource IsActive Beat Effects do Director does
1 · No OSC false false null idle (standalone) ✓ standalone timer ✓
2 · OSC live, no clock
bpm=-1 / beat_in_bar=-1 — between tracks, deck idle		 true false null idle (standalone) ✓ nothing — frozen ✗
3 · OSC live, real beat true true N react ✓ synced sequencing ✓

State 2 is reachable and proven: BeatManagerRaveOscIntegrationTests.cs:77–101 asserts IsLiveSource == true while IsActive == false for a sentinel-bpm snapshot. On the rig this is "OSC software open, no track playing." The effects degrade gracefully; the Director stalls — no rotation, no transitions, and its standalone rotation timer never ticks because TickStandaloneMode is never reached.

Rendering keeps running (Controller.cs:1609), so the wall isn't black — it shows one effect in its idle behavior, unchanging. Worse, a beat-domain cue loaded while synced is still started from Unity time (StartLoadedCueIfDue), because nothing clears it on the (never-taken) mode exit. That is the High finding from the branch review, and it lands here: teardown belongs at the mode boundary that does not currently exist.

Recommendation: one predicate, owned by BeatManager

The mode question is a deep predicate scattered as a shallow re-derivation across five consumers. Concentrate it. BeatManager already owns the snapshot, IsActive, and IsLiveSource — it is the natural owner of the answer. The effects already consume the right predicate (IsActive); the fix is to make every other consumer read the same one.

Recommendedin-process

A · Single predicate authority

Make "usable clock present" (today's IsActive) the mode authority on BeatManager. Director's IsSyncedMode and Tick route on it with a real standalone else. IsLiveSource demoted to pure connectivity diagnostics.

  • locality: one predicate, one place to change
  • effects unchanged — they already read it
  • freeze (state 2) collapses into standalone
  • leverage: every consumer agrees by construction
Worth exploringenum + event

B · Mode enum with transition hook

Same authority, but expose SourceMode and raise on change so consumers can run entry/exit work — Director clears the loaded cue and resets the cue planner on entering standalone.

  • gives the mode boundary a real seam
  • home for cue teardown (the High finding)
  • only justified once a 2nd consumer needs the transition
Hotfix onlyband-aid

C · Patch the Tick gate

Make Tick fall to TickStandaloneMode when Beat is null even while live. Unfreezes the wall.

  • smallest possible change
  • still two definitions of standalone
  • no single source of truth — the thing you asked for

Design decisions to settle before coding (ADR-worthy):

  • Authority = usable clock, not transport. Mode keys off IsActive; IsLiveSource survives only as "is OSC connected?" for diagnostics/HUD. Confirm that matches the rig intent (between-tracks should be standalone, not a wait).
  • Fold the floor in. PhaseLock.StandAloneFloor (beat_in_bar < 1) and IsActive (bpm > 0) are separate thresholds that happen to travel together in the sentinel. Decide whether the one authority is "bpm > 0", "beat_in_bar ≥ 1", or both — then everyone derives from it.
  • Mode boundary owns teardown. Entering standalone must reset the cue planner and clear the Switcher's loaded cue (today only the former happens, and only when the never-reached TickStandaloneMode runs).
  • Tests at the seam. Add a Director/BeatManager mode-boundary test: live + sentinel → standalone, loaded cue cleared, standalone timer ticks. The current suite covers StandAloneFloor only at the PhaseLock unit level.

Top recommendation

Adopt Option A, with Option B's transition hook only if cue teardown needs it.

One predicate on BeatManager answers "usable musical clock?". The Director and the HUD stop reading IsLiveSource for mode; the effects keep reading exactly what they read now. State 2 stops being a hole because there is no longer a second opinion about what standalone means. If you want the freeze gone today, ship Option C as a stopgap — but it is not the source of truth you're asking for, so treat it as a bridge to A, not the destination.
