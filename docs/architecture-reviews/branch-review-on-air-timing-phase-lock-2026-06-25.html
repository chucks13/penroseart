What Went Right

The module depth improved.

The old broad timing module was collapsed into clear interfaces: PhaseLock, PhraseTracker, PhaseGrid, and Director-owned CuePlanner. The interface surface is smaller and the implementation now hides real behavior.

The tests exercise caller-visible seams.

PhaseTimelineHarness, PhaseLockTests, PhraseTrackerTests, and retargeted CuePlannerTests cover loops, phrase dropouts, track changes, irregular phrases, cue sheet behavior, and mandatory cue invariants.

The old resolver is gone.

PhaseClock.cs and PhaseClockTests.cs are deleted in favor of the stateful phase determiner. Shared grid math lives in PhaseGrid.

Cue planning moved to the right owner.

CuePlanner owns cue sheet derivation, cursor, cadence, and pass-local cue memory instead of round-tripping that state through timing.

Attribution And Scope

A later counter-review correctly checked these findings against master. That attribution matters: Director.IsSyncedMode already keyed off OSC transport liveness, and Switcher.cs is unchanged by this branch. Those are not new regressions in the narrow diff sense.

The merge question is broader than diff attribution. This branch introduces and documents StandAloneFloor, while the PRD says the Director's existing mode machinery acts on that floor. In the current code, it does not. So the precise finding is: inherited Director/Switcher behavior prevents this branch's new floor signal from satisfying its claimed end-to-end contract.

If the branch is merged as a pure model refactor, the docs and issues should explicitly say StandAloneFloor is emitted but currently unconsumed. If the branch is merged as the PRD implementation, the Director/Switcher mode seam needs tests and code before merge.

Findings

Critical mode seam

StandAloneFloor is produced but not consumed; live no-clock can freeze sequencing.

The design says beat_in_bar == -1 is the floor: exit synced mode and run the Director's free-running timer. PhaseLock emits StandAloneFloor, but Director.Tick never reaches it when live OSC is present but the beat query is unavailable. IsSyncedMode is transport liveness, and the synced branch returns even when Beat is null.

Attribution: the liveness-vs-usable-clock mode decision is inherited from master. The branch-specific gap is that the new floor signal is documented as actionable but remains orphaned at the Director mode seam.

Evidence: Assets/core/Switching/Director.cs:193-195, Director.cs:283-290, Assets/core/Switching/PhaseLock.cs:101-105, Assets/core/Rhythm/BeatManagerRaveOscIntegrationTests.cs:77-101.

Impact: the wall can stop scheduling changes while OSC is still broadcasting sentinel/no-clock data.

High Switcher execution

Pending beat-domain loaded cues can survive a mode exit.

TickStandaloneMode resets the timing frame and CuePlanner, but it does not clear the Switcher's loaded cue. Switcher.RenderAtTime still calls StartLoadedCueIfDue from Unity time. A cue loaded while synced can therefore start after the Director has moved to standalone/no-clock behavior.

Attribution: Switcher.cs is byte-for-byte unchanged against master. This is a pre-existing execution lifetime, not a regression introduced by this branch. It still belongs in this report because any fix that makes StandAloneFloor exit synced mode must also define what happens to already-loaded beat-domain cues.

Evidence: Assets/core/Switching/Director.cs:427-431, Assets/core/Switching/Switcher.cs:293-310, Switcher.cs:364-367, Switcher.cs:424-456.

Impact: stale musical intent can execute after the live timing source is no longer valid.

High track reset

Track-change reset is local to PhaseLock, not the full scheduling seam.

PhaseLock drops its held offset on TrackOrdinal changes, but CuePlanner receives no track-change signal. It preserves lastCueBeat, lastChangeBeat, cue sheet cursor state, and any Switcher loaded cue. Because CueSheet.Matches is length-only, a same-length phrase in the next track can reuse the previous track's cue sheet/cursor instead of starting a clean interpretation.

Nuance from the counter-review: UpdatePhraseWindow re-anchors the phrase window and a beat reset can rewind the cursor, so the worst stale-beat misfire may be masked. That does not prove the behavior benign; same-length phrase reuse still carries randomized cue pattern and cadence state unless a track-change reset is defined and tested.

Evidence: Assets/core/Switching/PhaseLock.cs:111-120, Assets/core/Switching/CuePlanner.cs:392-400, CuePlanner.cs:418-425, Assets/core/Switching/CueSheet.cs:108-114.

Impact: new songs can inherit prior-song cadence/cue state unless the surrounding mode/liveness path happens to reset it.

Overall Assessment

The branch did the hard architectural work well. It replaced a shallow timing/cue interface with deeper modules, moved cue planning to the Director side, retained deterministic seams, and added meaningful tests. The code is easier to reason about than the pre-branch shape.

The problem is that the new phase floor is not yet wired into the actual runtime mode decision. The system can represent "clock gone" inside PhaseReading, but the Director can bypass the reading entirely when OSC transport remains live and the beat query is absent. The underlying mode behavior predates this branch; the branch-specific issue is that the new contract and docs imply that behavior is now handled. Separately, Switcher loaded-cue state outlives Director timing resets, which must be specified when the mode exit is wired.

Recommendation: either wire StandAloneFloor through the Director/Switcher mode seam and add tests, or explicitly descope that behavior in the PRD/issues/redesign doc as a follow-up. Then reconcile the remaining stale docs and re-run the full Unity suite. After that, this branch looks close.
