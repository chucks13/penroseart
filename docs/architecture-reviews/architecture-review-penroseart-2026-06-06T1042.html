Problem. MixerBase is shallow — 33 lines, a pass-through Init(), one filter loop. Solution. Deepen MixerBase: child spawning, lifecycle ordering, and the recursion guard become its implementation; the three stray child-owning effects move under it (or call its helper).

  • locality: child lifecycle bugs concentrate in one module
  • recursion guard covers all 6 child-owners
  • hidden ordering contract becomes implementation
  • delete 7 copies of the ritual

3 · Wire expansion belongs to the Penrose model

Strong in-process

Assets/core/Controller.cs:581–593 (ACN/UDP) · Assets/core/Controller.cs:615–625 (serial) · Assets/core/Penrose.cs

Before — mapping smeared across two output paths

sendSerialFrame · Controller.cs:615

wires[i]/2 → physical LED order

sendUDPFrame · Controller.cs:581

wires[i]/2 → physical LED order (same mapping, second copy)

Penrose — owns JsonRawData.wires but not the mapping

After — mapping is Penrose's implementation

Penrose

ExpandToWires(tiles, physical)

· 900 tiles → 1800 LEDs · wires[i]/2 · pure, headless-testable

serial adapter

frame pack + send

ACN adapter (legacy)

universe pack + send

Two adapters = real seam.

Problem. The tile→physical-LED contract (wires[i]/2) leaks out of Penrose into Controller, duplicated in the serial and legacy ACN paths. A wiring change means two edits; frame packing for the hardware is untestable.

Solution. Penrose — which already owns the wires data — exposes the expansion; both output paths consume it. Behavior-preserving.

  • locality: wiring contract lives where the data lives
  • two adapters (serial, ACN) justify the seam
  • tests: pure 900→1800 mapping, headless
  • delete one duplicated loop
⚠ Touches the serial/ACN output path — AGENTS.md requires explicit sign-off before changing hardware paths, even behavior-preserving refactors. Validate against the board contract.

4 · Deepen palette loading to match the Waveform Pool

Worth exploring in-process

Assets/core/helpers/GPalette.cs (AnimPalette ctor :140, readfile :218, processhex :253, processgradient :287) · exemplar: Waveform Pool (ADR-0001)

Before — AnimPalette constructor

reads Controller.Instance.paletteSource ← singleton leak at construction

readfile(): catch (Exception) → "" ← failure becomes "no palettes"

processhex(text) ← twin macro scanners,

processgradient(text)   same IndexOf/substring walk

Cannot test parsing without a live Controller; cannot tell "empty file" from "could not read."

After — the shape the Pool already proved

Palette module

Parse(text) → palettes

· pure: one DEFINE-macro walk for hex + gradient
· logs malformed entries, never silently empty

file read at the edge — missing ≠ unreadable (as WaveformPool.ReadFileOrEmpty does)

Problem. Two hand-rolled parsers for the two StreamingAssets text formats, in two shapes: the Waveform Pool's parse is pure and tested (15 tests); AnimPalette mixes file I/O, a Controller-singleton read, and twin macro scanners inside a constructor, and converts every I/O failure into an empty palette set.

Solution. Reshape palette loading to the Pool's proven form: pure parse, file read at the edge, failures visible. Same creative-coding idiom — no new framework.

  • tests: palettedata.txt parsing, headless
  • failures surface instead of vanishing
  • one parse idiom across both data files
  • interface shrinks; constructor stops owning I/O

5 · Name the playing ⇄ transition state machine

Speculative in-process

Assets/core/Controller.cs (inTransition flag, timer callbacks, deck draws ~:1084–1131) · Assets/core/TransitionBase.cs

Before — implicit, smeared

bool inTransition — the whole state model
Timer callback decides next state
deck draw + OnStart scattered in callbacks
transitions reach back into controller.effects[A], [B]

Testing a transition means driving Controller.Update() in a scene.

After — one named module inside Controller

stateDiagram-v2
  direction LR
  Playing --> Transitioning : effect timer ends /
draw from decks
  Transitioning --> Playing : transition timer ends /
promote B

Controller keeps ownership; the show schedule becomes one testable module with a small interface.

Problem. The effect/transition alternation — the heart of the show — is an implicit state machine spread across a boolean, timer callbacks, and deck plumbing. Its rules can only be exercised through a full scene.

Solution. Concentrate the alternation (states, deck draws, A/B handoff) into one named module Controller owns and drives. Not a Controller breakup — a deepening of one responsibility inside it.

  • locality: show-scheduling rules in one place
  • tests: state transitions without a scene
  • transitions stop reaching across the seam for effects[A/B]
⚠ Controller is intentionally central (AGENTS.md): any restructuring beyond small wiring needs explicit approval. Surfaced because the friction is real — the state machine is the least-testable core behavior — but this card is a question, not a plan.

Smaller observations (noted, not candidates)

  • Assets/core/Transition.cs — documented legacy class ("retained for reference"); concrete subclasses would still be Factory-discovered as effects.
  • EffectBase.OnEnd() exists but is never invoked — a hidden non-contract; effect authors may rely on it.
  • ScreenEffect statics (width/height/neighbors) initialize on first subclass init — fine single-threaded, but an undocumented part of the interface.
  • BeatDataDrawer (~1,000 lines) names BeatData fields as strings — renames in BeatData silently break the drawer.

Top recommendation

1 · Deepen the Beat Pulse interface on EffectBase

Highest leverage for the least risk: 21 verified call sites collapse onto one accessor, no hardware path is touched, and it finishes what ADR-0001 started — the Waveform Synthesizer is already deep; this deepens the side that consumes it. Candidate 2 is the natural second: it turns the one module that currently fails the deletion test (MixerBase) into one that passes it, and closes a real recursion-guard gap.
