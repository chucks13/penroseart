1 · What got split, and why

One 244 KB single-line JSON blob (rawdata.json) used to carry four unrelated things. They change at different rates, so they now live in separate documented text files. The pattern never changes; the wiring changes every time the hardware does. That is the seam.

3 · How the app picks a wiring — the #define

Top of Assets/core/Runtime/Controller.cs, right next to the existing ENABLE_SERIAL. Define exactly one. Neither defined = compile error, not a wrong wall. 

#define ENABLE_SERIAL

// Select the wiring diagram for this art piece: define exactly one.
// Wiring files are hand-editable text in Assets/StreamingAssets (wiring_*.txt).
#define WIRING_6X5
//#define WIRING_ORIGINAL

On startup the log prints which files loaded: [Controller] Layout: penrose_layout.txt; wiring: wiring_6x5.txt (1800 LEDs).

4 · The wiring file format — what you actually edit

// lines are comments; the rest is JSON. One {"leds":[…]} entry per physical output string, in output order. Each number is the half-tile index (0–1799) that LED displays, listed in daisy-chain order along the wire — first number = first LED on the string. 

// =============================================================================
// Penrose Wall - WIRING: new art piece (6 outputs x 300 LEDs)
// … (header documents everything below) …
// =============================================================================
{
"outputs":[
{"leds":[1455,1496,1497,1495,1453, … ,1,0]},   ← output 0, 300 entries
{"leds":[1552,1556,1553, … ]},               ← output 1
 …
{"leds":[ … ,301,300]}                       ← output 5
]
}

How one number becomes light

LED #7 on output 0
reads entry 7 →
1493
÷ 2 →
tile 746
→ that LED shows tile 746's color

Two LEDs per tile (one per triangle): half-tile indexes 2k and 2k+1 both belong to tile k. Even = triangle A, odd = triangle B.

  • All outputs together must use every number 0–1799 exactly once — it's a permutation.
  • Output count and lengths are free: 6×300 today; 4×450 tomorrow would parse fine.
  • Global LED index (what the S2 Mini boards claim in their handshake) = position after flattening the outputs in order: output j of 300 owns globals j·300 … j·300+299.

5 · The edit loop when the hardware arrives

  1. Wire the strings; write down, per output, which half-tile each LED hits in chain order.
  2. Open wiring_6x5.txt in any editor; replace the numbers in the matching leds array.
  3. Restart the app (or re-focus Unity and press Play). Check the startup log line.
  4. Wrong tile lighting up? Swap the numbers, restart. That's the whole loop.

Mistakes fail loud at startup — the wall never scrambles silently.

  • "Wiring LED index 1493 appears more than once."
  • "Wiring LED index 1800 is outside 0..1799."
  • "Wiring file has no outputs." / "Wiring file contains an empty output."
  • Bad JSON (missing comma/bracket) → parse exception naming the file.

A duplicate always implies a missing number somewhere else — fix both ends.
