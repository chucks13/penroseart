# How Things Are Done in PenroseArt

## Code organization conventions

- There are currently **no custom `.asmdef` files**; project-authored runtime code compiles into Unity's generated `Assembly-CSharp` assembly.
- Classes are mostly in the global namespace. Do not assume namespace scoping exists.
- Most filenames match class names and use PascalCase, but some existing classes are lowercase (`fluid`, `kscope`, `lightning`, `yinyangmixer`, `drums`). Match surrounding style when editing existing files; prefer PascalCase for new public types unless deliberately aligning with an existing effect name.
- Unity-generated project files (`*.csproj`, `.slnx`) should not be hand-edited; Unity regenerates them.
- `.meta` files under `Assets/` are intentionally kept; `.gitignore` ignores `*.meta` globally but un-ignores `Assets/**/*.meta`.

## Adding or editing effects

New visual effects normally subclass one of:

- `EffectBase` for direct 900-tile generative effects.
- `ScreenEffect` for rectangular 2D algorithms that need conversion to the Penrose tile layout.
- `MixerBase` for wrappers/mixers that own child effects.

Expected effect shape:

```csharp
public class MyEffect : EffectBase
{
    public override string DebugText() { ... }

    public override void Init()
    {
        base.Init();
        // one-time allocation/setup
    }

    public override void OnStart()
    {
        base.OnStart();
        // randomize per-run state, clear buffers if needed
    }

    public override void OnEnd() { }

    public override void Draw()
    {
        // fill buffer[] every frame
    }
}
```

Important patterns:

- `base.Init()` binds `Controller.Instance`, `penrose`, `tiles`, and allocates `buffer = new Color[Penrose.Total]`.
- `base.OnStart()` enables beat response and assigns a random `beatVariant`.
- Effects usually use `EffectBase.APalette.read(...)` for color harmony instead of hardcoded colors.
- Beat-aware effects use `beatManager.GetBeatBrightness(...)` or `beatManager.GetBeatTime(...)`.
- Clear or reinitialize per-run state in `OnStart()`, not in constructors; effects are long-lived.
- `Factory<EffectBase>` discovers all concrete non-abstract subclasses automatically, so adding a public concrete subclass changes the effect pool.

## Adding transitions and blenders

- New effect-to-effect transitions subclass `TransitionBase` and implement `OnStart()`, `OnEnd()`, and `Draw()`.
- `TransitionBase.A` and `B` are indexes into `controller.effects`; `V` is clamped transition progress and `D` is `1 - V`.
- `TransitionBase.Blend(...)` may also be used as an external-source blend mode when `ActiveTransitionBlender` is set.
- New external-source blenders subclass `BlenderBase` and implement `Usage()` plus `Blend(Color[] dest, Color[] src1, Color[] src2)`.
- `settings` for transitions/blenders come from `setFaders(string[])`, which parses floats from command arguments.

## Runtime flow conventions

- `Controller.Start()` owns setup. It initializes `Penrose`, UI fields, effects, transitions, blenders, OSC, drums, pixel receiver, optional camera overlay, timer, and serial output.
- `Controller.Update()` is the central per-frame loop. Most runtime behavior passes through it: timer, palette, beat manager, effect/transition drawing, overlays, blending, output, mesh preview, and OSC ping.
- Effect/transition selection uses integer decks. `pullCard()` chooses from the top half and moves the selected index to the bottom.
- The Nova testing override (`forceEffect`/`forceEffectName`, Escape toggle) bypasses random effect selection by substring matching `effects[i].Name`.
- `startEffect` exists in serialized state but current `SetupEffects()` ignores it and calls `GetNewEffectIndex()`.

## Data and asset conventions

- `Penrose.Total` is fixed at 900 logical tiles.
- Current `Penrose.Awake()` reads JSON from scene-serialized `Controller.Instance.jsonSource`, not directly from `StreamingAssets/rawdata.json`; treat the scene field as the current runtime source unless this is deliberately changed.
- `StreamingAssets/rawdata.json` and `rawdata1.json` are still useful references and appear to contain the same shape counts, with `rawdata1.json` differing by one `loops` entry count.
- Shape-list data in `JsonRawData.shapes` is used by effects such as `Mirror` and `kscope`; preserve array formats unless you update all consumers.
- `kscope` reads images from `StreamingAssets/images/color` and `StreamingAssets/images/mono`; on non-Android it writes `files.txt` directory listings.

## Conditional compilation conventions

- `Assets/core/Controller.cs` currently has file-local `#define ENABLE_SERIAL`, so serial output is active in that file regardless of ProjectSettings scripting symbols.
- `ENABLE_TELNET` and `PREP_CAPTURE` code paths exist but are inactive unless defines are added.
- ProjectSettings currently has empty `scriptingDefineSymbols: {}`.
- `Assets/core/Controller - nova.cs` is wrapped in `#if false` and is a disabled alternate/reference implementation.

## Reusable infrastructure reminder

Before adding helpers or systems, read `penroseart-what-you-can-reuse`; this project already has reusable base classes, factories, palette/beat helpers, mapping utilities, output helpers, and OSC/UDP infrastructure.
