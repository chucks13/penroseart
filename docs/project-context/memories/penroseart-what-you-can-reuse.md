# What You Can Reuse in PenroseArt

Use these existing systems instead of recreating new equivalents.

## Effect base classes

### `EffectBase`

**Purpose:** Base contract for direct generative effects that output a 900-tile `Color[]` buffer.

**Location:** `Assets/core/Effects/EffectBase.cs`

**How to use:** Subclass it, call `base.Init()` and `base.OnStart()`, implement `DebugText()`, `OnEnd()`, and `Draw()`, and write colors into `buffer`.

**Use instead of:** Creating independent effect lifecycle managers or per-effect MonoBehaviours.

### `ScreenEffect`

**Purpose:** Converts rectangular 2D visual algorithms into the irregular Penrose tile buffer.

**Location:** `Assets/core/Effects/ScreenEffect.cs`

**How to use:** Subclass it, draw into `screenBuffer`, then call `ConvertScreenBuffer(ref screenBuffer, in buffer)`.

**Use instead of:** Recomputing 2D-to-Penrose interpolation weights in every effect.

### `MixerBase`

**Purpose:** Base for wrapper/mixer effects that own child effects.

**Location:** `Assets/core/Effects/MixerBase.cs`

**How to use:** Subclass it when an effect needs child effects; use `GetRandomEffect()` so child selection avoids recursive mixers.

**Use instead of:** Hand-rolled child-effect discovery that can accidentally nest mixers.

### `TransitionBase` and `BlenderBase`

**Purpose:** Shared contracts for effect-to-effect transitions and native/external-source pixel blending.

**Locations:** `Assets/core/Transitions/TransitionBase.cs`, `Assets/core/Blending/BlenderBase.cs`

**How to use:** Subclass `TransitionBase` for transition drawing between `controller.effects[A]` and `controller.effects[B]`; subclass `BlenderBase` for external pixel-source blending.

**Use instead of:** Adding special cases to `Controller.Update()` for every transition or blend mode.

## Runtime discovery and selection

### `Factory<T>`

**Purpose:** Discovers concrete subclasses of a base type and instantiates them by reflection.

**Location:** `Assets/core/helpers/Factory.cs`

**How to use:** `Controller` already uses `Factory<EffectBase>`, `Factory<TransitionBase>`, and `Factory<BlenderBase>`. New non-abstract subclasses are automatically included.

**Use instead of:** Maintaining manual effect/transition/blender registries.

### Deck selection

**Purpose:** Avoids immediate repeats by choosing a random item from the top half of a deck and moving it to the bottom.

**Location:** `Controller.initDeck()` and `Controller.pullCard()` in `Assets/core/Runtime/Controller.cs`

**How to use:** Reuse the existing deck mechanism for random-but-varied selection.

**Use instead of:** Naive `Random.Range(0, count)` selection for user-facing effect order.

## Shared visual helpers

### `AnimPalette` / `GPalette`

**Purpose:** Global palette parsing, animation, and color sampling.

**Location:** `Assets/core/helpers/GPalette.cs`; shared instance `EffectBase.APalette`.

**How to use:** Sample colors with `APalette.read(position, interpolate)` where `position` is normalized. Trigger global palette shifts with `EffectBase.APalette.Change()`.

**Use instead of:** Hardcoding independent palettes per effect.

### `BeatManager`

**Purpose:** Simulated rhythmic clock with beat variants, brightness pulses, and time warping.

**Location:** `Assets/core/Rhythm/BeatManager.cs`; instance `Controller.beatManager` and `EffectBase.beatManager`.

**How to use:** Call `GetBeatBrightness(...)`, `GetBeatTime(...)`, and assign/use `beatVariant` from `EffectBase.OnStart()`.

**Use instead of:** Per-effect rhythm timers.

### `ExtensionMethods`

**Purpose:** Common helpers for buffers, colors, and numeric mapping.

**Location:** `Assets/core/helpers/ExtensionMethods.cs`

**How to use:** Reuse helpers like `Color[] Clear()`, `Fade()`, `MinBrightness()`, `Map()`, and `Map01()`.

**Use instead of:** Duplicating buffer clearing, fade, and mapping code inside effects.

### `Perlin`

**Purpose:** Perlin noise utility used by multiple effects.

**Location:** `Assets/core/Effects/Perlin.cs`

**How to use:** Call `Perlin.Noise(...)` for procedural effects.

**Use instead of:** Bringing in a second noise implementation without a clear reason.

## Penrose model and data

### `Penrose` / `JsonData` / `TileData`

**Purpose:** Holds the 900-tile layout, mesh, bounds, shape lists, physical wire mapping, and lookup helpers.

**Location:** `Assets/core/Runtime/Penrose.cs`

**How to use:** Access `controller.penrose`, `penrose.Tiles`, `penrose.JsonRawData.shapes`, `penrose.JsonRawData.wires`, and `Penrose.Total`.

**Use instead of:** Parsing wall geometry or shape data independently inside effects.

## I/O infrastructure

### `SerialOut`

**Purpose:** Discovers ESP32-S2/S2 Mini serial LED boards, handshakes their pixel ranges, and sends frame data from background I/O threads.

**Location:** `Assets/core/Hardware/SerialOut.cs`; protocol notes in `Assets/core/Hardware/S2_MINI_PROTOCOL.md`.

**How to use:** Current `Controller` calls `serial.send(serialOutputBuffer, brightness)` through `sendSerialFrame()` when `ENABLE_SERIAL` is active.

**Use instead of:** New serial-port scanning or per-board packet code.

### E1.31/ACN UDP output

**Purpose:** Sends physical LED data in DMX/E1.31-style UDP universes.

**Location:** `Controller.setupUDP()`, `sendUDPFrame()`, and `sendACN()` in `Assets/core/Runtime/Controller.cs`

**How to use:** This path is currently inactive because `ENABLE_SERIAL` is file-defined. If re-enabling it, verify channel order and await/error behavior.

**Use instead of:** A separate UDP output implementation unless the existing one is intentionally replaced.

### OSC and UDP helpers

**Purpose:** OSC control and simple UDP receive infrastructure.

**Locations:** `Assets/OSCReader.cs`, `Assets/OSC.cs`, `Assets/core/IO/UDPControllers.cs`, `Assets/core/IO/PixelReceiver.cs`, `Assets/core/ReactiveInputs/drums.cs`

**How to use:** `Controller.Start()` adds `OSCReader`; `PixelReceiver` handles UDP pixel data on port `7778`; `drums` handles drum/ring overlays.

**Use instead of:** Adding new one-off UDP listeners without considering existing ports and thread behavior.

## UI/helper infrastructure

### `Singleton<T>`

**Purpose:** Provides the `Controller.Instance` pattern.

**Location:** `Assets/core/helpers/Singleton.cs`

**How to use:** Existing code depends on `Controller : Singleton<Controller>`. Be cautious: `Instance` creates a GameObject if none exists.

**Use instead of:** A second singleton implementation.

### `Timer`

**Purpose:** Simple countdown timer with normalized progress and completion callback.

**Location:** `Assets/core/helpers/Timer.cs`

**How to use:** `Controller` uses it for effect and transition durations.

**Use instead of:** Duplicated frame-based countdown logic.

### `SliderScript`

**Purpose:** UI slider binding for brightness and text display.

**Location:** `Assets/core/helpers/SliderScript.cs`; scene object `Slider`.

**How to use:** Existing scene wiring references `Controller.brightness` and a TMP label.

**Use instead of:** Adding a second brightness UI controller.
