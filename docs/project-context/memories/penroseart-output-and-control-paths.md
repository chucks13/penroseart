# PenroseArt Output and Control Paths

## Current active output path: USB serial

`Assets/core/Controller.cs` has a file-local `#define ENABLE_SERIAL`, so the compiled `Controller.Update()` output path is:

```text
penrose.buffer (900 tiles)
  -> Controller.sendSerialFrame()
  -> serialOutputBuffer (wires.Length, currently 1800 LEDs)
  -> SerialOut.send()
  -> S2 Mini board threads
```

`sendSerialFrame()` maps each physical LED index with:

```csharp
serialOutputBuffer[ptr1] = data[wires[ptr1] / 2];
```

Then `SerialOut.send(serialOutputBuffer, brightness)` snapshots the frame and signals board I/O threads.

### `SerialOut` protocol behavior

`Assets/core/SerialOut.cs` currently:

- Ignores the `Init(int baudRate)` argument and hard-codes `targetBaudRate = 2000000`.
- Scans `SerialPort.GetPortNames()` periodically.
- Opens candidate ports with DTR/RTS enabled.
- Waits 2 seconds after opening for ESP32-S2 USB CDC boot behavior.
- Sends `CMD_QUERY` (`?`, `0x3F`) to identify LED boards.
- Expects board type `0x01`, payload size, start index, and pixel count.
- Starts one background I/O thread per discovered board.
- Sends `CMD_DATA` (`D`, `0x44`) + start/count + RGB bytes, then appends `CMD_LATCH` (`L`, `0x4C`).
- Exposes debug info listing OS ports, active boards, connecting ports, and ignored ports.

Protocol docs live at `Assets/core/S2_MINI_PROTOCOL.md`, but they drift from code in details: the doc mentions both 2,000,000 baud and Arduino `Serial.begin(230400)`, a 200ms boot delay, and immediate `FastLED.show()`, while current code uses 2,000,000 baud, a 2-second wait, and latch byte. Confirm firmware behavior before changing protocol.

## Alternate/legacy output path: E1.31/ACN UDP

If `ENABLE_SERIAL` is removed/undefined, `Controller.Update()` calls `sendUDPFrame()` instead.

The UDP path:

- Uses destination IP from scene field `Controller.IP`, currently serialized as `192.168.1.253`.
- Uses E1.31 default port `5568`.
- Maps `JsonRawData.wires` to a byte buffer with channel order **R, B, G**.
- Sends DMX-sized 510-byte chunks via `sendACN()`.
- Increments sequence in `acnheader[111]`.

Known caveat: `sendACN()` is `async Task`, but `sendUDPFrame()` calls it without awaiting. This can hide send exceptions and allow overlapping frame sends.

## Incoming OSC control

`Controller.Start()` adds `OSCReader` dynamically and sets `Controller.OscHandler` as the all-message handler.

`OSCReader` defaults:

- Local input port: `6969`.
- Outbound IP: `192.168.1.255`.
- Outbound port: `6161`.
- Background thread receives packets; Unity `Update()` dispatches queued messages.

`Controller.OSCpage1()` handles the main OSC UI/control page. Observed behavior includes brightness, NYE toggle, effect buttons, effect period, and `/ping` replies. `Controller.OscHandler()` has an empty `/beat` branch; current beat behavior is internally simulated by `BeatManager`, not driven by OSC.

## PixelReceiver external source

`PixelReceiver` listens on UDP port `7778` and receives a packet stream into a 900-color buffer.

- Packet context `0x00` means RGB pixel data.
- The packet has a 6-byte header and byte offset; `byteOffset / 3` gives destination pixel index.
- Receiving data sets `timeout = 100` frames so `Controller.Update()` treats the pixel source as active.
- If an `ActiveBlender` or `ActiveTransitionBlender` exists, it blends native and external buffers; otherwise the external pixel buffer replaces `penrose.buffer`.

## Drums overlay

`drums` opens UDP port `8500` and can draw hit/ring overlays over the current Penrose buffer.

- Number keys `1`-`5` trigger drum hits in editor/runtime testing.
- Number keys `6`-`0` trigger rings.
- `drums.Draw(penrose.buffer)` overlays after the active effect/transition and optional filter.

## Camera overlay

`CameraReader` is disabled in the current scene (`useCamera: 0`). If enabled, it:

- Requests webcam authorization.
- Starts a `WebCamTexture`.
- Samples/mixes webcam data through a virtual screen buffer.
- Uses `ScreenEffect.ConvertScreenBuffer()` to map camera output to Penrose tiles.

## Conditional Telnet server

`Assets/core/helpers/TelnetServer.cs` is entirely behind `#if ENABLE_TELNET`.

If enabled, it listens on port `23` and registers commands:

- `help`
- `echo`
- `list effects`
- `list blenders`
- `effect <name> [time]`
- `blender <name> [values]`
- `nye on|off`
- `dummy on|off` only when `PREP_CAPTURE` is active

`TelnetServer.Service()` appends command I/O to root `log.txt`.
